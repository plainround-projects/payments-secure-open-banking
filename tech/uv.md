# uv

## What it is

`uv` is a fast command-line tool for Python packaging, written in Rust. It can create environments, install packages and, as used here, **resolve** requirements: take loose rules such as "fastapi 0.115 or newer, below 1" and work out one exact, compatible version of every package.

## Why this repository uses it

Only for one job: producing the two hash-pinned lock files (`requirements.lock` and `requirements-dev.lock`). The rest of the project uses plain `pip`, so a reader needs `uv` only if they want to refresh the pins. Nothing at run time, test time or in CI depends on it.

## Where it appears

| Path | What it does with uv |
| --- | --- |
| `Makefile`, target `lock` | Runs `uv pip compile` twice. |
| `requirements.lock`, `requirements-dev.lock` | Their first two lines record the exact `uv` command that produced them. |

## How it works underneath

`uv pip compile` reads `pyproject.toml`, asks the package index (PyPI) for every candidate version, picks the newest set that satisfies every package's own rules, downloads the file hashes, and prints the result in `requirements.txt` format. It does not install anything and does not change your environment.

## Walkthrough of this repository's use

```make
lock: ## regenerate the hash-pinned lock files from pyproject.toml (needs uv)
	uv pip compile pyproject.toml --generate-hashes --python-version 3.12 -o requirements.lock
	uv pip compile pyproject.toml --extra dev --generate-hashes --python-version 3.12 -o requirements-dev.lock
```

- `pip compile pyproject.toml` resolves the `dependencies` list.
- `--generate-hashes` adds a `--hash=sha256:...` line for each downloadable file, which `pip install --require-hashes` later checks.
- `--python-version 3.12` resolves as if running on Python 3.12, the lowest version the project supports, so the lock works there even if you run the command on 3.13.
- `--extra dev` also resolves the optional `dev` group (pytest, ruff, mypy and others). Only the second file includes it.
- `-o requirements.lock` writes the result to that file.

Reading the output: each package has `==version`, its hashes and a `# via ...` comment naming who needs it.

## Try it yourself

1. Check it is installed:

   ```bash
   uv --version
   ```

   Expected: a line like `uv 0.11.2 (...)`. If the command is not found, install it from the official instructions; you do not need it for any other `make` target.

2. Preview a resolution without touching the repo files:

   ```bash
   uv pip compile pyproject.toml --python-version 3.12 | head -20
   ```

   Expected: pinned names and versions with `# via` comments and no hash lines (hashes are off without `--generate-hashes`).

3. Compare: `make lock && git diff --stat`. With no new releases the diff is empty; with new releases only the two lock files change.

## Mistakes people make

- **Running `uv pip compile` on a different Python minor version without `--python-version`.** The result may pull packages that do not install on the lowest supported version. The Makefile fixes the target version.
- **Confusing `uv pip compile` with `uv lock`.** `uv lock` writes a different file (`uv.lock`) in uv's own format. This repository uses the `requirements.txt` style that plain pip reads.
- **Hand-editing the lock.** The header says it is autogenerated; edit `pyproject.toml` and regenerate.

## Check yourself

1. Which `make` targets need `uv`? *Only `make lock`.*
2. What does `--generate-hashes` add? *A SHA-256 line per allowed file, so pip can verify what it installs.*
3. Why pass `--python-version 3.12`? *To resolve for the oldest supported Python, whatever Python runs the command.*
4. What does `# via pydantic` mean? *The package is in the lock because pydantic requires it.*
5. Does `uv pip compile` install packages? *No, it only writes a resolved list.*
