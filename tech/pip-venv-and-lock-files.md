# pip, virtual environments and hash-pinned lock files

## What it is

Python programs rely on other people's packages (FastAPI, psycopg, pytest). **pip** is the tool that downloads and installs them from the Python Package Index (PyPI). A **virtual environment** (venv) is a private folder, here `.venv/`, holding its own copy of Python's package folder, so this project's packages do not mix with other projects' packages. A **lock file** lists the exact version of every package, and here also a fingerprint (a hash) of each file, so every machine installs exactly the same bytes. **setuptools** is the build tool that turns the project's own source into an installable package.

## Why this repository uses it

A payments service must be reproducible. If a new release of a library changes behavior, or a package on the network is swapped for a malicious one, the money rules could silently change. Pinning every version and verifying every hash means `make install` gives the same result today, in CI, and in the Docker image.

## Where it appears

| Path | Role |
| --- | --- |
| `pyproject.toml` | Declares the project, its loose requirements (`fastapi>=0.115,<1`) and the `dev` extra (test and lint tools). |
| `requirements.lock` | The exact runtime versions with hashes (471 lines). Used by the Docker image. |
| `requirements-dev.lock` | Runtime plus development tools with hashes (1533 lines). Used by `make install` and CI. |
| `.venv/` | The virtual environment (not committed; listed in `.gitignore`). |
| `.venv/.installed` | An empty "stamp" file that tells `make` the install is done. |
| `Makefile` | Targets `install`, `$(STAMP)` and `lock`. |
| `Dockerfile` | Runs `pip install --require-hashes -r requirements.lock`. |

## How it works underneath

- `python -m venv .venv` creates the folder, copies or links the interpreter, and creates `.venv/lib/python3.x/site-packages/`, the place installed packages land.
- Running `.venv/bin/python` (instead of the system `python`) makes imports look in that folder. Nobody has to "activate" anything; the `Makefile` calls the programs by their path.
- A **wheel** (`.whl`) is a ready-built package file. pip downloads wheels from PyPI and unpacks them into `site-packages`.
- `--require-hashes` makes pip refuse any file whose SHA-256 is not listed in the lock file. It also requires every package to be pinned with `==`.
- An **editable install** (`pip install -e .`) installs the project as a link to `src/`, so edits take effect without reinstalling. It also creates the command-line programs named under `[project.scripts]`.

## Walkthrough of this repository's use

### The loose requirements

From `pyproject.toml`:

```toml
dependencies = [
    "fastapi>=0.115,<1",
    "uvicorn>=0.32,<1",
    "psycopg[binary,pool]>=3.2,<4",
    "pyjwt[crypto]>=2.9,<3",
    "httpx>=0.27,<1",
]
```

Each line is a **version range**: any version from the first number up to, but not including, the next major version. `pyjwt[crypto]` asks for the `crypto` extra of PyJWT, which adds the `cryptography` package (needed for the elliptic-curve signatures, see `jwt-and-dpop.md`). `psycopg[binary,pool]` asks for two **extras**: `binary` (a prebuilt C library so no compiler is needed) and `pool` (the `psycopg_pool` package).

The `dev` extra (`[project.optional-dependencies]`) adds pytest, pytest-cov, hypothesis, ruff, mypy, import-linter and pip-audit. You install it with `pip install -e ".[dev]"`; the lock file already contains it.

### The lock files

The top of `requirements.lock`:

```
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --generate-hashes --python-version 3.12 -o requirements.lock
annotated-doc==0.0.5 \
    --hash=sha256:117bac03... \
    --hash=sha256:c7e58ce0...
    # via fastapi
```

- `==0.0.5` pins one exact version.
- Each `--hash=sha256:...` is an allowed file for that version (there is one hash per wheel, for each platform).
- `# via fastapi` says why this package is here: `fastapi` needs it. The lock covers the whole **dependency tree**, not just the four direct requirements: pydantic, starlette, anyio and h11, and every other package listed in the file.
- The trailing `\` joins lines, like a long command in a shell.

Selected pins at the time of writing: `fastapi==0.162.0`, `uvicorn==0.54.0`, `psycopg==3.3.6`, `psycopg-pool==3.3.3`, `httpx==0.28.1`, `pydantic==2.14.1`, `starlette==1.10.0`, `pyjwt==2.15.1`, `cryptography==50.0.2`, `cffi==2.1.1` (the last is the bridge `cryptography` uses to call its compiled code).

### Creating the environment

```make
$(STAMP): requirements-dev.lock pyproject.toml
	$(PYTHON) -m venv $(VENV)
	$(VENV)/bin/pip install -q --require-hashes -r requirements-dev.lock
	$(VENV)/bin/pip install -q --no-deps -e .
	touch $@
```

1. The target is the stamp file. It depends on both lock and `pyproject.toml`: if either is newer than the stamp, `make` runs the recipe again.
2. `-m venv .venv` creates the environment.
3. The first `pip install` installs only what the lock lists. `-q` is quiet. `--require-hashes` is the safety check.
4. The second installs this project itself. `--no-deps` stops pip from resolving anything (the lock already did), `-e .` makes it editable.
5. `touch $@` creates the stamp; `$@` means "the target".

### Regenerating the lock

```make
lock:
	uv pip compile pyproject.toml --generate-hashes --python-version 3.12 -o requirements.lock
	uv pip compile pyproject.toml --extra dev --generate-hashes --python-version 3.12 -o requirements-dev.lock
```

This resolves the ranges to exact versions again. `--python-version 3.12` picks versions that work on 3.12 even if your machine runs 3.13. It needs `uv` (see `uv.md`). Run it only when you want newer packages, then commit the new lock files.

### In the Docker image

```dockerfile
COPY requirements.lock ./
RUN pip install --require-hashes -r requirements.lock
```

The runtime lock (without test tools) is installed first, and the project source is copied afterwards, so Docker can reuse the cached layer when only the code changes.

## Try it yourself

1. See which packages the environment has:

   ```bash
   .venv/bin/pip list | head -15
   ```

   Expected: a table with `Package` and `Version` columns, starting with `annotated-doc 0.0.5`.

2. Ask why a package is installed:

   ```bash
   .venv/bin/pip show httpcore | grep -i "required-by"
   ```

   Expected: `Required-by: httpx`.

3. Check the project is installed as editable:

   ```bash
   .venv/bin/pip show payments-secure-open-banking
   ```

   Expected: `Name: payments-secure-open-banking`, `Version: 0.1.0` and an `Editable project location:` line pointing at this folder.

4. Prove the stamp logic: `touch pyproject.toml && make install` reinstalls; running `make install` again does nothing.

## Mistakes people make

- **Installing into the system Python.** Packages from different projects clash. Always use the venv's `pip`.
- **Loose pins in production.** `fastapi>=0.115` could install a different version tomorrow. The lock removes that.
- **Editing the lock by hand.** Regenerate it with `make lock`; hashes cannot be guessed.
- **Committing `.venv`.** It is machine-specific and large; `.gitignore` excludes it.
- **Forgetting `--no-deps` with hash mode.** Without it pip would try to resolve extra dependencies it has no hashes for and fail.

## Check yourself

1. What is the difference between `pyproject.toml` requirements and a lock file? *The first states acceptable ranges; the lock states exact versions and file hashes.*
2. What does `--require-hashes` protect against? *Installing a file that is not the one that was locked, for example a tampered package.*
3. Why is there a `.venv/.installed` file? *It is the stamp `make` compares against the lock files to decide whether to reinstall.*
4. Why are there two lock files? *One for runtime only (smaller Docker image), one with the development tools.*
5. Why does the Docker image copy `requirements.lock` before `src`? *So the slow install layer stays cached when only source code changes.*
